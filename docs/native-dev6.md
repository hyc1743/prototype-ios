# native-dev.6 图元与音频修正

针对两次实机反馈中的开场后黑屏、杂音，以及 native-dev.4 启动黑屏回归。

## 渲染

原生渲染器原先在 geometryShader=false 时直接跳过点、矩形和四边形。
dev.4 加入的细分路径没有通过用户实机验证，已从生产构建移除。

本版接入固定 SDK 已有的 kPointListAsTriangleStrip 与
kRectangleListAsTriangleStrip 顶点着色器实现。矩形着色器执行三个原始顶点，
选择对角线并生成第四角；点精灵保留尺寸和坐标输出。宿主使用两个明确的三角形，
无需 geometry shader 或新增细分阶段。

索引绘制先把原始索引按其端序和宽度归一化到共享流，交给 SDK 读取；宿主
使用 32 位合成顶点编号，自动索引和 DMA/立即索引分别处理。四边形按
原 geometry shader 的 0,1,3,2 条带顺序生成两个三角形。

运行复现还定位到深度清除兼容处理的命令顺序错误：它关闭当前渲染通道后，
调用方仍提交绘制。现将该处理移到主通道开启前，回归测试分别验证旧顺序
会使绘制落到通道外、新顺序会正确开启通道。SDK 未处理的宿主异常不再
反复返回同一条故障指令，而是交还系统异常处理。

矩形循环的程序计数取值指令改为在全部入口加入后生成。Apple 平台将每次
提交限制为最多 128 次绘制，避免首个场景把数千次绘制集中到一个 Metal
命令缓冲。每段沿用原来的提交、栅栏和渲染通道状态管理。

渲染通道复用改为严格匹配颜色和深度附件集合。旧实现只检查本次需要的附件，
会把上次的深度或额外颜色附件留在通道内，与按本次附件创建的管线不匹配。
新增回归复现覆盖移除 MRT、移除深度和切换到纯深度绘制；相同附件仍可复用。
该修正的场景运行验证尚在执行。

五个动态常量缓冲改为逐绑定更新描述符。其顶点/像素阶段掩码不同，不能用
一次跨绑定写入更新；新增测试同时验证阶段规则与五个缓冲的槽位映射。

## 音频

实机日志显示六声道逻辑设备；第二次启动每 10 秒消费约 1876 个缓冲，
没有缺帧补零。这不能证明缓冲里的音频可听，也不支持单靠增加队列修复的结论。

Apple 平台本版提交 SDK 的明确立体声混音。游戏音频请求改为每 256/48000 秒
进行一次，减少设备一次拉取多个缓冲时集中请求 guest 回调的情况；等待使用
sleep_until，保留 8 帧请求上限。Apple 生产线程直接把混音写入 SDL 流，
根据流的排队量推进游戏回调，避免在设备回调取不到 guest 缓冲时主动插入
静音块。旧配置中的 dev.4 队列值会自动迁移，其他设置保留。
日志加入实际输出峰值、有效采样数和非有限采样数，不再仅计数缓冲数量。

## 验证范围

索引测试覆盖图元边界、三角形顺序、残缺尾部和超过 16 位的合成编号。
真实 Apple 运行观察与 iOS 编译分别执行，结果单独附在 Release；
macOS 运行结果不能替代 iPhone 的实际验证。
GPU 丢失、提交失败、未处理的宿主异常或着色器验证失败，即使进程最终
正常退出，也必须按运行失败记录；不能只凭构建和进程存活判定成功。

保留游戏图标和英文默认值。覆盖安装时保留 game/ 与 saves/，无需重导资源。
新 log.txt 启动行应显示 build=6 renderer=sdk-vertex-expansion audio=stereo-paced。
