## 音频

nxnative 记录过设备每次要求 1024 个采样、生产队列只有 960 个采样而造成
周期性补零的复现，iOS 前端因此请求约 5 ms 的 AVAudioSession 缓冲。
它还给音频释放通知线程配置交互 QoS，并按输出设备单独记录实际回调与欠载。
d2r-mobile 明确把六声道混为双声道，避免隐式转换丢失中置对白。

Prototype 已有明确立体声混音及直接 SDL 流提交。最新 macOS 观察中，提高
供音线程优先级后，每 10 秒由约 700–800 帧恢复为约 1875 帧。
本次另给 iOS 请求 256/48000 秒的会话缓冲、256 帧 SDL 设备缓冲，并在
回到前台或中断结束时恢复会话偏好，记录系统实际采用的采样率与时长。
不同音频后端和设备不保证接受相同缓冲；macOS 供音正常不能证明 iPhone 无杂音。

## 后期合成

nxnative 的记录包括两种相关失败：

- Metal 快速数学可能丢弃翻译着色器依赖的 NaN/Inf 语义；它使用 relaxed 数学，
  并对需要 IEEE 行为的 min/max/clamp 使用 precise 函数。
- 正确的中间纹理通过错误的 2D/数组视图采样后可变为统一颜色；其 `tex_fit`
  将实际纹理维度与着色器反射维度匹配。

Prototype 观察 `40019551471` 的正常渲染组已取得九张中间图：第二至第四张
可见人物、天空，最后一张全黑。关闭深度测试与剔除的组同样在最后变黑。
这把重点指向纹理复制、后期采样和合成，尚不能据此确定是哪一项。
SDK 的普通 2D 采样声明为数组图像，原生缓存也提供数组视图；不能直接把它们
全部改成普通 2D。下一步按实际着色器与绑定逐项核对。

测试工具新增 MoltenVK 快速数学模式对照（自动模式 2 / 禁用模式 0）。
另抓取 Prototype 后期步骤的输入纹理和常量。原始着色器诊断以现有构建密钥
认证加密后上传，避免把游戏着色器作为公开诊断文件分发。

后续观察 `40022209457` 的正常组在捕获开始前已发生 GPU timeout / device
lost，因此本轮黑色读回内容无效，不能用来推翻此前的中间场景图，也不能用来
确定复制或采样失败。246 个翻译着色器通过 SPIR-V 验证，静态检查确认后期
着色器声明普通 2D 采样时使用 `texture2DArray`，与当前视图类型相符。
数学模式对照 `40024314706` 已完成：自动模式 2 和禁用模式 0 都无 GPU 丢失，
但最终截图仍只有 HUD、世界背景黑。不能把关闭快速数学当作本次黑屏修复。
四种后期阶段的同场景对照 `40029499272` 已完成：保留原顶点程序时纯色输出仍黑，
固定全屏顶点后纯色完整可见。后续 GPU 读回确认原始顶点与 CPU 上传一致。

iOS 内部构建 `40027920753`（源码 `fbfda7008bd66202a040684b62b330d5f32a568e`）
已通过编译与独立 IPA 核验：53,211 个翻译函数、iOS 设备平台标记、游戏图标、
英文默认值和音频会话缓冲设置均存在，渲染器源码摘要也与该提交重新准备的文件一致。
IPA SHA-256 为 `d6c83a60d03aff032215190758336a3700a45cbaa1726fe7651307c20d10ae5f`。
该包只用于内部检查，不证明画面或 iPhone 扬声器输出正常。

本地七个原生修正用例已编译执行通过，包含修正前失败、修正后通过的渲染通道
及描述符规则复现；运行观察的五个测试也通过。单元测试不替代场景运行观察。

后续 `40037757308` 的指定顶点程序算术对照恢复完整人物、街道和战斗画面。
原始数据和像素程序保持使用，只有该顶点程序的严格运算标记被去除；249 个
着色器验证通过，无 GPU 丢失。该兼容现已默认开启，详见 `native-dev6.md`。
默认配置复测 `40040616405` 恢复场景，关闭兼容的对照 `40040621374` 重现黑屏。
最终 iOS 包 `40040383604` 通过独立核验并已发布为 `v0.1.0-native-dev.6`；
该包的 IPA SHA-256 为 `4a9354cd743448279475946af4bf76ef2a48e24610b177fc0f9a9892ff80735e`。
